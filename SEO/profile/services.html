How an engagement runs

1. Diagnose

A short call or written brief. I tell you what is in scope, what is not, and a realistic timeline.

2. Ship in PRs

Work lands as reviewable pull requests with notes — the same habit as the open-source page.

3. Measure

For product work: Lighthouse, Search Console, and the metric we agreed (LCP, INP, conversion, or ticket volume).

Typical problems I take

The site is built in React and invisible to Google

I add crawlable HTML (SSR/SSG or prerender), titles, canonicals, and internal links — then verify with a no-JS view.

Core Web Vitals are failing

Hero image, main-thread JS, layout shift. I have cut load ~40% and INP ~20% on large apps; I start from measurement, not guesses.

Auth and APIs feel unsafe

Tokens, rate limits, headers, validation, and error handling — the same features I already merged on a public Node API.

A candidate needs a senior mock

I run the round, then we rewrite answers so they sound like an engineer who has shipped, not a checklist.
